# Environment and Deploy Facts

- **Host:** Linux VM (this machine). Python 3.12.3. Pipecat **1.8.0**. Server venv: `~/workspace/ai-calling/.deploy-venv`.
- **Server:** FastAPI app in `server/live_server.py`, listens on 127.0.0.1:8001. systemd unit `ai-calling-live` (source in repo `systemd/ai-calling-live.service`). Pipeline built by `server/live_pipeline.py::build_live_pipeline`.
- **Public ingress:** Pinggy Pro tunnel, hostname `aqlmfmjrsk.a.pinggy.link` (unit `ai-calling-pinggy`, ssh to pro.pinggy.io:443). Telnyx Call Control app webhooks + media point at `https://aqlmfmjrsk.a.pinggy.link` (wss for `/telnyx/media/<attempt_id>`). Pinggy passes WebSocket upgrades correctly (verified 101 externally). The previous tunnel (tunl) provably cannot.
- **EGRESS PROXY (critical):** all outbound traffic from this VM goes through an HTTP egress proxy that **TLS-intercepts** (peer cert issuer "Hatch Sandbox Egress CA") and re-originates WebSocket 101 responses with `Connection: close`. This already broke the ElevenLabs handshake once (fixed in code — see 01). Any new outbound WebSocket client in this codebase must be evaluated against this behavior. `~/.config/egress-proxy.env` holds the proxy env; `~/.config/proxy-connect.sh` is the CONNECT helper used as ssh ProxyCommand.
- **Readiness gate:** `GET /readyz` requires (a) valid public host, (b) provider env keys present, (c) the provider-preflight receipt `logs/provider-preflight.json` with `ready:true` and **younger than 3600s** (TTL!), (d) the fixed-phrase cache populated. The preflight runs at service start (prestart) and validates Groq/Gemini/ElevenLabs only — never Telnyx.
- **VM replacements:** the runtime replaces this VM without warning; `/etc/systemd/system` units are wiped each time (project files under `~/workspace` survive). Restore = re-run `tools/deploy_linux.sh`, reinstall units from `systemd/`, restart. This happened twice during Oct 29–30 testing and destroyed the journal evidence for call #4.
- **Dialer:** `tools/dial_qualification_20261029.py` — registers a media job via `POST /internal/register-media-job` (internal token), claims via the Telnyx adapter, dials, on answer issues `streaming_start` with `wss://<public-host>/telnyx/media/<attempt_id>`, then monitors the attempt state until hangup or caps (10 min / $1.00). Transcript/cost records are expected in `logs/qualification-call-2026-10-29.jsonl` keyed by call_control_id.
- **Phrase cache:** fixed phrases (incl. the disclosure opening) are pre-synthesized into `logs/phrase-cache` namespaced `<voice>/<model>/pcm_<rate>`; readiness fails if any required phrase is missing from the cache.
- **NLTK:** sentence tokenization for TTS aggregation needs `punkt_tab`; data lives in `~/workspace/ai-calling/nltk_data` via `NLTK_DATA` env in the unit. NLTK's own downloader fails here (SSRF guard vs the proxy's 198.18.x address) — the package was fetched with curl through the proxy.
